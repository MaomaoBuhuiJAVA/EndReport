# 科学馆逐步落地

## 已实现

- 磁力打捞、沉浮实验、影子工坊均为可直接操作的游戏；成长手册、每日积分、年龄分组周榜已接入页面。
- 游客记录保存在当前设备。登录用户可以主动开启账号手册；账号孩子档案和游戏完成记录由服务端按当前登录账号隔离。本机历史不会自动上传。
- 服务端按收到事件的时间计算北京时间日期和积分。每个孩子每天每款游戏首次完成 +10 分，每天最多 30 分；完成事件 ID、数据库唯一约束和事务支持安全重试与去重。
- 断网期间的账号完成事件进入本机待同步队列，联网后可重试。补交积分按服务端收到记录的日期计算，界面会标明待同步状态。
- 联网周榜按年龄分组，接口只返回榜单展示所需的孩子昵称、头像、积分和主题数。
- PostgreSQL 补丁位于 `prisma/patches/science-games.sql`；Prisma 模型、API、离线队列和路由测试均已在代码库中。

## 当前验证

历史记录：`npx vitest run src/lib/science-games` 为 8 个测试文件、72 项通过；科学游戏相关 ESLint 和全仓 `npx tsc --noEmit` 通过。此前本地预览的中班联网周榜连续 5 次返回 HTTP 200。集成测试使用独立 PGlite 数据库，不会连接或修改网站配置的数据库。

早期本地预览曾因本机数据库 URL 格式不符而让联网周榜返回 HTTP 503；该结果不代表 ECS 数据库状态。

## ECS 发布复核（2026-10-23）

首次生产切换时，页面和文档下载检查通过，但周榜接口返回 HTTP 503，发布流程自动恢复旧版本。只读诊断确认 ECS 的 `DATABASE_URL` 带有 Prisma 专用 `schema` 与 `connection_limit` 参数；`postgres.js` 将它们当作 PostgreSQL 启动参数，服务端因此拒绝连接。SQL 补丁当时已成功提交，回滚保留了三张游戏表与数据库备份。

`src/lib/science-games/server-db.ts` 现在在创建 `postgres.js` 客户端前移除这两个 Prisma 专用参数，并保留其他连接选项。新增的 `server-db.test.ts` 覆盖参数清理。修复后候选实例的只读周榜请求返回 HTTP 200，`/api/games/leaderboard?age=中班` 返回空榜及 `2026-10-19` 至 `2026-10-26` 的周区间。

r7 已在阿里云 ECS 上线。全项目 88 个测试文件、823 项通过；发布流程测试 24 项通过。生产验收 13 项通过，包含三款游戏页面、周榜数据库接口、DOCX/PDF/PPTX/XLSX 导出、下载文件跨重启保留和私有媒体边界。上线过程未调用付费模型，暂存阶段未写数据库；正式迁移只新增游戏表，未删除积分数据。真实家长账号跨设备流程和 iPhone、安卓、微信内置浏览器仍未实测，具体范围见 [QA.md](QA.md)。

## 后续部署与磁盘维护

每次上线都要把本次实际运行的代码和对应部署/验收文档提交并推送到 GitHub，发布记录写明分支、提交 SHA、线上版本和验收结果。只发布本次变更所需的文件，不把主工作树里的其他未提交内容混入发布。

每次部署前后检查系统盘用量，清理确认无用的临时构建目录、包管理器缓存、失败候选包和过期发布归档。失败版本如需排查，先归档到本机并校验 SHA-256，再清理服务器副本。新版本通过健康检查和关键业务验收后，服务器只保留当前线上版本与上一稳定版本用于快速回滚；更早且未被服务、定时任务或回滚流程引用的发布目录及 bundle 可删除。

清理时不得删除当前线上目录、上一稳定版本、数据库备份、用户上传文件、媒体数据或运行配置。先检查目录引用关系并确认备份完整，再删除；清理后复查磁盘空间、`guoke-web` 与 Nginx 状态、首页和关键 API。若上线验收失败，保留失败现场所需日志并恢复上一稳定版本，不以清缓存或删归档替代故障诊断。
