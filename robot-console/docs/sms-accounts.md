# 短信登录与账号管理

`/auth` 提供密码注册、密码/短信登录、找回密码和修改绑定手机号。注册不要求短信验证码，新账号的手机号标记为未验证；验证码登录、找回密码和换绑手机仍需验证短信。短信未开通时显示“开通中”；不提供模拟验证码，不假报短信发送成功。手机验证不授予管理员权限或家长投稿身份。老师仍需现有园方注册码。

服务端优先使用 `SMS_ACCESS_KEY_ID` / `SMS_ACCESS_KEY_SECRET`，未设置时复用既有 `ALIBABA_CLOUD_ACCESS_KEY_ID` / `ALIBABA_CLOUD_ACCESS_KEY_SECRET`。RAM 凭据需要 `dysms:SendSms` 权限，OSS 权限本身不包含短信发送权限。临时 STS 凭据填写 `SMS_SECURITY_TOKEN`（兼容原 STS 配置）。`SMS_VERIFICATION_SECRET` 使用独立随机字符串，至少 32 字符。

## 审核完成后的接入顺序

1. 在授权部署时备份现有 PostgreSQL，执行增量补丁 `prisma/patches/20261010-sms-accounts.sql`。补丁仅新增验证码表和用户会话版本，不删除用户、手机号、密码及业务数据。
2. 配置已审核的签名、上述模板、实际模板变量以及具备短信发送权限的密钥；先保持 `SMS_ENABLED=false`。
3. 构建部署生成新的 Prisma Client；数据库补丁必须先于新版应用启动。密码/手机改动的会话版本校验也依赖此补丁。
4. 审核通过后设置 `SMS_ENABLED=true` 并重启应用。以授权测试手机号验证四类流程，确认收到真实短信，再开放使用。

本地页面已经预接入服务代码；没有执行生产 SQL、修改真实密钥或发送真实短信。审核尚未完成时无需启用开关。

## 管理员用户列表

`/admin/users` 仅供绑定手机号为 `13967719299` 且角色为 `ADMIN` 的账号使用。每次管理员验证都需要向该号码发送短信验证码；验证后管理员专用会话有效 15 分钟。`POST /api/admin/auth/send-code` 与 `POST /api/admin/auth/verify` 是独立门禁，不接受普通登录会话或其他手机号。用户列表接口只选择账号资料、注册时间和最近登录时间/方式，不返回邮箱、密码哈希或验证码数据。密码使用单向哈希保存，无法读取或展示原密码。

## 接口与验证规则

`GET /api/auth/sms` 返回公开开通状态，不返回密钥、验证码、签名或模板代码。`POST /api/auth/sms/send` 接收 `phone`、`purpose`；成功返回 `challengeId`、60 秒重发等待及 300 秒有效期。

`/api/auth/sms/login`、`/api/auth/password/reset` 接收手机号、对应 `challengeId` 和 6 位 `code`。重置密码另需 `newPassword`。`/api/auth/register` 接收姓名、可选用户名、手机号、密码、家长/老师身份与老师注册码，不接收短信凭证或客户端验证标记。

`/api/auth/phone` 需要已登录账号、新手机号和新手机的验证码；已绑定手机同时提交当前手机的 `currentChallengeId` / `currentCode`。没有绑定手机号的历史账号通过账号密码加新手机验证码绑定。新手机验证码与当前会话账号绑定，不能用于其他人的绑定请求。改手机号不修改账号角色或作品关系。

`/api/auth/username` 由当前有效登录会话提交新用户名，无需重复输入密码；保留同源校验、格式与唯一性检查，并递增会话版本、重新签发当前会话。修改密码仍需原密码，修改手机号仍需对应验证码。

验证码摘要保存在既有 PostgreSQL。校验绑定手机号、用途和账号，5 分钟失效、最多 5 次错误、成功后单次消费；旧新手机的两份验证码在同一事务中校验及消费。发送先由数据库锁预留，限制同手机号 60 秒间隔、5 次/小时、20 次/天，同来源 20 次/小时、60 次/天，以及整个服务 500 次/天；失败发送也计入额度以限制滥用。每次发送清理超过 48 小时的记录；停用或无发送时，旧记录延至下一次发送清理。不要将此表放入公开接口或导出用户记录。

生产反向代理必须覆盖 `X-Forwarded-For` 并仅向受控代理开放应用端口；用户提供的来源头不能作为可信 IP。即使来源头失效，手机号限制和全站总额度仍有效。

密码重置及手机号变更递增会话版本，使旧 cookie 失效；密码修改和手机号变更重新签发当前会话。浏览公开资源仍不要求登录。验证码/会话/数据库错误均不包含服务密钥或供应商详细响应。
