# AI 平台与开发过程说明

## （一）平台/技术选择

本项目采用 Dify Cloud Chatflow，构建“龙湾区国科温州第二幼儿园园所信息智能体”。智能体面向家长、访客和教师，承担园所概览、科学资源、功能室、荣誉资质和实验活动等内容的中文问答任务。

平台由以下技术组成：

- **Dify Chatflow**：用于定义智能体角色、回答边界、知识库检索、分支路由和对话流程。网页服务端通过 Dify `POST /v1/chat-messages` 调用已发布的智能体，Dify 内部使用的模型由 Chatflow 配置管理。
- **通义 AIGC 插件**：使用 Dify Marketplace 插件 `sawyer-shi/tongyi_aigc`（v0.0.4）。图片分支使用其中的 `Qwen-文生图` 工具（`qwen-image-2.0-pro`）生成科学诗封面和教学配图，文件由“通义 AIGC 科学诗封面交付”节点传回；插件还提供图生图、图片翻译和视频生成工具。文字对话和资料检索仍由 Chatflow 的对话模型负责。该插件的“图生图/图片翻译”不等同于通用视觉问答；需要识别实验照片时，必须另接支持视觉输入的模型，并在未接入时明确提示无法直接识图。
- **服务端适配器**：在 Next.js Route Handler 中保存 Dify API 密钥，向 Dify 发送 `inputs`、`query`、`response_mode`、`user` 和可选 `conversation_id`，只把 `answer` 和会话编号返回浏览器。
- **Next.js + TypeScript**：用于实现官网页面、实验室资源中心、对话界面和服务端接口，前后端在同一项目中部署。
- **Prisma + PostgreSQL**：存储园所资料、知识分块、科学资源、照片、功能室及用户数据。
- **Vercel**：用于持续部署网站和服务端接口；模型密钥仅配置在服务端环境变量中。

## （二）开发过程

### 1. 明确智能体角色与回答范围

在 Dify Chatflow 的系统提示词中设置角色为“龙湾区国科温州第二幼儿园园所信息问答助手”。回答范围限定为园所公开资料和科小贝科学资源，并明确以下规则：

- 优先依据资料库内容回答；
- 资料库没有明确依据时，回答“资料库暂未收录明确内容”；
- 回答面向家长、访客和教师，保持简洁、温和、可信；
- 涉及功能室、空间、环境和参观时，提示用户查看相关图片；
- 不向普通用户输出云宝设备状态、实时监控、日志和控制细节。

可复用的核心提示词如下：

```text
你是“龙湾区国科温州第二幼儿园”的园所信息问答智能体。
请优先依据已检索到的园所资料和科小贝科学资源回答。
若资料库没有明确依据，不要编造，并说明“资料库暂未收录明确内容”。
回答要适合家长、访客和教师阅读，简洁、温和、可信。
当问题涉及功能室、空间、环境、照片、图片或参观时，提醒用户查看下方相关图片。
不向普通用户提供云宝设备状态、实时监控、日志或控制细节。
```

### 2. 构建知识库

先将园所概况、办园资料、省二级评估自评报告、功能室资料、科学诗、科学故事和科学实验等材料整理为文本。系统将每份资料拆分为适合检索的知识片段，并保留资料标题、正文、图片、视频和二维码等关联信息。

用户提问后，Dify Chatflow 先检索其知识库并生成回答；网页服务端同时根据中文关键词、同义词和 n-gram 检索本地科学资源目录，仅用于生成资料来源、图片和实验详情链接。问候、感谢等纯闲聊会跳过本地资源检索，但仍通过 Dify 的 `conversation_id` 保留上下文。这样既能连续对话，也能保证网页中的资源入口指向本地真实条目。

需要生成图片时，路由进入通义 AIGC 分支：提示词策划节点先整理主题、年龄、构图和安全约束，再调用 `Qwen-文生图`；网页只接受 Dify 返回的可信图片文件或 Markdown 图片地址。若插件执行成功但返回空 `files`，接口会返回可重试的降级卡片，不把“已生成”文字误当成图片。

### 3. 设计交互逻辑

智能体对话采用“提问 - 检索 - 生成 - 展示来源 - 继续追问”的流程：

1. 用户在网页右下角的智能体对话框输入问题。
2. 服务端按需检索本地科学资源目录，准备来源、图片和详情链接。
3. 服务端将问题和会话编号发送到 Dify Chatflow，由已发布的智能体检索知识库并生成中文回复。
4. 页面同时展示命中的资料来源；当用户询问功能室或环境时展示相关照片。
5. 当命中科学诗、科学故事或科学实验时，显示“查看《资料名称》”入口；用户点击后直接打开实验室的对应详情弹窗。
6. 模型服务未配置、超时或暂时不可用时，系统自动使用资料库检索结果生成回退回答，保证基础问答不中断。

### 4. 编写代码与接口

前端使用 React 组件实现悬浮对话窗口、消息列表、来源卡片、图片卡片和实验详情跳转。服务端通过 `POST /api/ai-chat` 接收用户问题，调用 Dify Chatflow，并把本地资源匹配结果合并为结构化响应。

接口返回 `reply`、`sources`、`photos` 和 `labLinks` 四类数据：

- `reply`：智能体生成的中文回答或资料库回退回答；
- `provider`：`dify` 或本地 `fallback`；
- `conversationId`：Dify 返回的多轮会话编号；
- `sources`：回答依据的资料标题；
- `photos`：与功能室或环境问题相关的图片；
- `labLinks`：可直达实验室详情弹窗的科学资源链接。
- `agentResult`：通义图片、视觉观察、实验复盘等结构化结果；图片结果包含模型名、提示词和安全的图片地址。

这种结构使模型输出与页面交互解耦：即使更换底层大模型，资料来源、图片和实验详情跳转仍由系统控制，功能可稳定复用。

### 5. 形成可复用技能

项目将“园所资料问答”沉淀为可复用的智能体技能，包含：角色提示词、资料检索规则、上下文拼接规则、回答限制、来源展示和异常回退六部分。迁移到其他园所时，只需替换资料库内容、园所名称和少量提示词，即可复用同一套对话流程。

复现步骤如下：

1. 在数据库中导入园所资料和科学资源，并为资料生成知识检索分块。
2. 在 Dify 中发布 Chatflow，安装并配置 Marketplace 中的 `sawyer-shi/tongyi_aigc` v0.0.4 工具节点（`Qwen-文生图` 模型选择 `qwen-image-2.0-pro`），并在网页服务端配置 `DIFY_API_KEY`；如使用自建 Dify，再配置 `DIFY_API_URL`。
3. 复制本说明中的角色提示词，配置 Dify 的系统提示词和知识库检索节点。
4. 启动项目后访问网页，在智能体对话框中输入园所、科学实验或功能室相关问题。
5. 分别测试普通问答和“生成《风的旅行》科学诗封面，3:4 竖版，无文字”；检查资料来源、详情入口和 `agentResult`。若通义节点返回空文件，确认页面展示可重试提示；断开模型服务后，确认资料库回退回答仍可用。

通过以上流程，项目实现了“智能体对话 + 园所知识库 + 科学资源直达”的完整闭环，并能够在不同园所资料场景中复现。
