# 《从园本资源到可执行活动：科小贝智能体助力幼儿科学教育》

## 一、课程定位

这不是一场单纯的产品演示，也不是代码培训，而是一场“教师如何把科小贝用成科学备课助手”的案例式工作坊。

建议授课对象为幼儿园教师、年级组长、教研组长和园所管理人员。标准时长为 90 分钟；如果希望每位老师都完成一次实操，可延长到 120 分钟。

课程要让老师听懂三件事：

1. 科小贝可以从园本资料中帮助教师找到科学诗、科学故事、科学实验和配套媒体。
2. 科小贝可以把教学要求整理成可修改的教案、活动回顾、课件提纲或探究任务。
3. AI 负责加快检索和整理，教师仍然负责年龄适宜性、安全审核和课堂最后决策。

## 二、开课目标

课程结束时，参训教师应能够：

- 从首页进入科小贝对话和科学资源库；
- 用“年龄段 + 主题 + 材料/现象 + 时长 + 输出要求”写出清晰提示词；
- 检索资源并打开真实的实验详情弹窗，查看步骤图片、视频入口和二维码；
- 生成一份完整教案初稿，检查活动过程和安全提醒，并下载 Word；
- 上传脱敏活动记录或实验图片，知道图片识别分支的适用范围；
- 识别 AI 输出中的事实、建议和待确认内容，不把未经审核的结果直接用于课堂。

## 三、课前准备

讲课前一天完成以下检查：

- 用电脑和手机分别打开生产网站，确认首页、智能体对话和 `/lab` 资源库可访问；
- 预先试跑一次资源检索、一次《玩转纸片》完整教案生成和一次 Word 下载；
- 准备一张没有儿童正脸、姓名和联系方式的实验材料图片；
- 准备一份脱敏的活动记录或教案文件，用于上传解析；
- 准备一个已经成功生成的科学诗封面作为图像生成的备用案例；
- 录制 2 至 3 分钟的演示录屏，网络或模型服务波动时播放录屏；
- 投屏前关闭 Dify 控制台、数据库后台和包含密钥的页面，不展示 API 密钥、账号或儿童隐私材料；
- 给每位老师准备一张“提示词公式 + 示例 + 安全边界”操作卡。

## 四、90 分钟课程安排

| 时间 | 模块 | 现场目标 |
|---|---|---|
| 0-8 分钟 | 开场与问题 | 让老师从真实备课痛点进入主题 |
| 8-18 分钟 | 平台认识 | 看懂首页、科小贝和科学资源库三个入口 |
| 18-33 分钟 | 资源检索与直达 | 找到资源并打开详情、图片、视频和二维码 |
| 33-53 分钟 | 完整教案生成 | 生成、审核并下载一份教案初稿 |
| 53-65 分钟 | 上传文档与图片识别 | 认识文件解析和视觉实验分析的正确用法 |
| 65-75 分钟 | 开发原理 | 用教师听得懂的方式解释数据库、知识库、工作流和代码 |
| 75-85 分钟 | 分组实操 | 每组完成一次检索和一次教案生成 |
| 85-90 分钟 | 边界、反馈与收尾 | 明确审核责任，收集下一轮资料需求 |

延长到 120 分钟时，将“分组实操”扩展到 30 分钟，并增加科学诗封面生成、作品反馈和实验复盘演示。

## 五、开场话术（可直接朗读）

“各位老师，今天我们不把科小贝当成替教师上课、替教师做决定的工具，而是把它当成一位熟悉园本资源的备课伙伴。老师遇到一个科学活动问题时，可以先向它提问；它会从园所资料和科学资源中寻找依据，再帮助我们形成活动初稿、找到步骤图片和配套视频。最后的年龄判断、材料安全和课堂决策，仍然由老师完成。今天我们用一个真实案例走完整条链路：提出备课问题，找到园本资料，生成教案，打开配套资源，下载并审核。”

开场可追问老师：“大家平时备一个科学活动，最花时间的是找资料、写教案，还是准备图片和视频？”把现场回答记在白板上，后面逐项演示解决。

## 六、逐段授课脚本

### 1. 认识平台：8-18 分钟

操作顺序：打开首页，指出科小贝入口，再进入科学资源库。不要先讲技术名词，先讲老师的使用路径。

可这样说：

“首页是入口，科小贝是对话助手，资源库是可以直接核对的园本内容。对话适合提出问题和继续追问，资源库适合按类型、年龄段和关键词浏览。两者不是互相替代，而是一个负责理解需求，一个负责让资源可查、可看、可复核。”

首页的轮换图片属于网站展示层；它与科学诗封面生成是两个不同功能，不要把首页图片切换误解为现场生成图片。

### 2. 资源检索与详情直达：18-33 分钟

先在对话框输入：

```text
推荐一个适合小班的关于风的科学实验，给出活动时长、材料、操作步骤，并告诉我有没有步骤图片、视频和二维码。
```

向老师解释：

“系统先判断这是资源检索问题，再从知识索引中找标题、年龄段和资源标识。网页端还会把命中的真实实验条目、图片、视频和二维码关联起来，所以我们看到的不是模型随口编的链接。”

然后继续输入：

```text
请打开《玩转纸片》的实验详情，展示材料准备图、按顺序排列的操作步骤图、视频和二维码。
```

点击“查看《玩转纸片》”入口，展示以下内容：

- 实验封面和活动基本信息；
- “材料准备 1、2……”与“操作步骤 1、2……”的顺序图片；
- “播放视频”按钮；
- 同一实验资源对应的二维码；
- 详情弹窗关闭按钮和移动端布局。

强调一个重要规则：“配套资源必须属于同一个实验条目。没有找到的视频或二维码就明确说暂未提供，不能用另一个实验来凑。”

### 3. 生成完整教案：33-53 分钟

从“更多功能 → 完整教案”打开表单，填写年龄段、主题、活动时长和输出格式。基础信息填好后，点击生成即可，不需要把同样的信息再复制进聊天框。

现场提问词：

```text
请生成《玩转纸片》完整教案，适合大班，活动时长 20 分钟，输出可下载的 Word。
```

生成后按下面顺序讲解：

1. 活动名称、年龄段、领域和活动时间；
2. 活动目标；
3. 活动重点与难点；
4. 活动准备；
5. 活动过程：导入、猜想、操作、观察记录、交流解释、总结和延伸；
6. 教师关键话术和幼儿可能的表达；
7. 观察记录、差异化支持和安全提醒；
8. 家庭延伸或下一次探究问题。

可直接说：

“完整教案的判断标准不是字数多，而是老师拿到后能不能照着准备和组织。尤其要检查活动过程是否完整、材料是否与过程一致、问题是否适合这个年龄段，安全提醒是否具体。下载的 Word 是可编辑初稿，不是未经审核即可使用的定稿。”

点击下载 Word，用 Word 或 WPS 打开后快速检查标题、表格、分页和中文显示。若现场网络不稳定，可展示事先下载的成功文件，并说明网页支持在模型未返回附件时根据生成内容生成 DOCX。

### 4. 上传文档与图片识别：53-65 分钟

#### 文档解析演示

上传脱敏的活动记录，输入：

```text
请把这份活动记录整理成面向家长的活动回顾，保留真实观察，缺失信息标记为“待补充”，并导出 Word。
```

说明文件链路：上传文件 → 解析正文 → 教研整理 → 格式审核 → 生成可下载文件。上传材料前要删除儿童姓名、联系方式、人脸和无关个人信息。

#### 图片识别演示

上传没有儿童隐私的实验材料图片，输入：

```text
请根据图片说明：1. 能直接看见哪些材料和操作；2. 哪些现象还不能确认；3. 给中班教师三条安全提醒。不要猜测图片外的内容。
```

讲解口径：

“普通 DeepSeek 文本对话不能直接看图片。图片会进入通义 qvq-max 视觉分支，由视觉节点先描述可见证据，再由 DeepSeek 整理成教师建议。图片模糊、遮挡或没有上传图片时，系统应该要求补充材料，不能为了完整而猜结论。”

视频也要如实说明：当前不能直接理解完整视频；如需分析，应提供关键帧或文字记录。

### 5. 开发原理浅讲：65-75 分钟

投屏展示下面这张简图：

```text
园本科学诗、故事、实验、图片、视频、二维码
                       ↓
网站数据库保存完整资源和真实媒体关联
                       ↓
Dify 知识库保存可检索的教学文本索引
                       ↓
智能体判断需求并进入对应能力分支
                       ↓
网页组合回答、来源、详情弹窗、媒体和下载入口
                       ↓
教师审核、修改后用于真实活动
```

用下面的顺序讲开发过程：

1. **整理资料**：把科学诗、科学故事、科学实验及园所资料统一清理标题、年龄段、主题、来源和媒体关系。
2. **建立数据库**：使用 Prisma + PostgreSQL/Neon 保存资源条目、图片、视频、二维码、用户和知识分块。完整媒体资源主要在网站数据库和静态资源中。
3. **建立知识库**：将可检索的教学正文整理成 Markdown，按类型和年龄段拆分后导入 Dify。Dify 的 Markdown 索引不是全部数据库，也不代替网站数据库里的视频和图片。
4. **设计提示词**：规定角色、资料依据、年龄适配、输出结构、隐私和安全边界，并要求没有依据时明确说“资料库暂未收录”。
5. **设计工作流**：Dify Chatflow 先做需求路由，再进入教学设计、资源检索、文档解析、课件创作、图片生成、视觉分析、实验复盘或作品反馈分支。
6. **接入模型和插件**：DeepSeek 负责中文对话、检索整理和教案写作；通义 qvq-max 负责实验图片的可见证据观察；通义 AIGC 的 Qwen-文生图负责科学诗封面和教学配图。
7. **编写网页接口**：Next.js 服务端调用 Dify，向前端返回 `reply`、`sources`、`photos`、`labLinks`、文件和结构化结果；前端据此渲染消息、详情弹窗和下载按钮。
  8. **测试与部署**：用固定测试问题检查年龄匹配、资源归属、图片顺序、二维码、文件下载和失败回退，再按阿里云 ECS 发布流程部署。密钥只放服务端环境变量，不放浏览器代码。

可以补充当前规模，但不要夸大：“当前资料包包含 163 条科学资源，其中科学诗 111 条、科学故事 28 条、科学实验 24 条。工作流按场景分流，不是一个模型包办所有事情。”

### 6. 科学诗封面生成（120 分钟版）

现场可使用已准备好的成功案例，或输入：

```text
请为科学诗《风的旅行》生成一张 3:4 竖版、无文字、幼儿绘本风格的科学封面，表现风吹动树叶和纸片的可观察现象，画面安全、明亮。
```

说明：该功能调用通义 AIGC 的 `qwen-image-2.0-pro`，新增科学诗时可将返回图片作为封面。图像服务依赖外部额度和网络，现场最好准备一张成功成品作为备用；不应把生成失败时的文字提示当成已经生成的图片。

## 七、提示词教学：让老师马上学会

把提示词归纳成一个简单公式：

> 年龄段 + 科学主题 + 教学目标 + 已有材料/现象 + 活动时长 + 希望得到的结果

对比讲解：

```text
不够具体：帮我写一个科学活动。

更容易得到可执行结果：
中班，主题是空气，活动 20 分钟。已有气球、纸条和吸管。
请设计包含猜想、操作、观察记录、教师提问和安全提醒的活动，
并输出一份我可以继续修改的完整教案初稿。
```

建议老师在第一次提问中给出约束，在第二次追问中做修改：

```text
把活动过程细化为“导入、猜想、操作、记录、交流、延伸”六段，
每段写出教师话术、幼儿可能的回应和预计用时。
```

再追问：

```text
请检查材料是否适合中班，删除危险或难以准备的材料，并列出仍需我确认的内容。
```

## 八、教师分组实操：75-85 分钟

每组选择一个年龄段和一个主题，完成以下三步：

1. 输入“推荐一个适合本年龄段的科学实验”，确认返回的主题和年龄是否匹配；
2. 继续要求生成包含完整活动过程的教案，并打开一个真实资源详情；
3. 互相检查输出，按“依据真实、年龄合适、步骤完整、资源可打开、安全可执行”五项打勾。

可选练习题：

```text
小班，主题是磁力，活动 15 分钟。请推荐一个园本实验，给出材料、猜想、操作步骤、观察记录和安全提醒，并附上同一实验的详情入口。
```

```text
大班，主题是纸桥，已有不同厚度的纸和积木。请生成完整教案，并列出需要在活动中记录的变量和下一步探究问题。
```

实操结束请每组提交一个真实备课问题和一份修改后的输出，作为后续知识库补充和产品改进依据。

## 九、常见提问与回答口径

**问：Dify 知识库是不是已经包含网站全部内容？**  
答：不是。Dify 主要保存整理后的 Markdown 教学文本索引；完整的视频、图片、二维码和资源元数据由网站数据库和静态资源管理。网页服务端把两边的真实标识关联起来，所以回答中的详情和媒体入口仍然来自网站真实条目。

**问：它是不是每次都能给出正确答案？**  
答：不能这样承诺。系统优先依据资料库；没有依据时应明确说未收录。教师要核对年龄、材料、时间、安全和本班实际情况。

**问：它能不能看视频？**  
答：当前不能直接理解完整视频。可以提供关键帧或文字记录，再使用图片识别或实验复盘能力。

**问：上传图片后为什么有时没有结论？**  
答：图片识别只对实际上传且清晰的图片工作，并且会把看不清的内容标成证据不足。普通文本模型不能替代视觉模型；遇到失败应补拍关键步骤或改用文字描述。

**问：生成的教案能不能直接使用？**  
答：它是可编辑初稿。教师必须审核活动过程、材料安全、年龄适宜性和时间安排，确认无误后再用于课堂。

**问：手机上的语音和通话是不是电话？**  
答：这是网页内语音输入、朗读和实时语音交互，不是拨打真实手机号码。是否可用取决于浏览器麦克风权限、语音识别和服务端音频配置。

**问：园所资料会不会被随意公开？**  
答：公开资料和登录权限分开管理；上传教研材料前仍应主动脱敏，不把儿童姓名、人脸、联系方式或内部敏感信息交给模型。

## 十、必须主动讲清的边界

- 科小贝是备课辅助工具，不替代教师的专业判断和安全责任；
- 普通 DeepSeek 文本节点不能直接识别图片和视频，图片必须进入 qvq-max 视觉分支；
- 不能从图片或文字推断儿童身份、健康、智力或能力等级；
- 模型、图像生成、语音和通话都依赖外部服务、网络、浏览器权限和额度；
- 没有真实来源时不编造视频、二维码、实验结论或下载链接；
- DOCX 下载后要在本机 Word/WPS 中抽查字体、分页、表格和图片；
- 真实机器人硬件协议尚未完整接入，当前主要完成网页、数据库和接口预留。

## 十一、网络或模型异常时的备用方案

1. 先播放准备好的演示录屏，不在现场反复刷新或暴露后台配置；
2. 使用已下载的《玩转纸片》教案和实验详情截图继续讲解“输出应该长什么样”；
3. 讲解本地资料库回退机制：模型暂时不可用时，网页仍可用真实资料生成基础回答；
4. 把实时图像生成、语音通话安排为可选演示，不让它们成为课程是否成功的判断条件；
  5. 记录错误现象和时间，课后再检查模型服务配置、ECS 运行环境和浏览器权限。

## 十二、结束话术
