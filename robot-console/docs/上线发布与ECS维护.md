# 上线发布与 ECS 维护

本项目正式运行于阿里云 ECS。每次线上更新都应留下 GitHub 提交和发布记录，并使用受控发布包对照服务器当前版本执行，不能直接覆盖运行目录。

## 发布步骤

1. 查看 Git 分支、未提交变更和线上当前版本；只选择本次相关文件，不使用 git add -A。
2. 运行相关测试、全仓测试、类型检查和本次文件的 ESLint。记录已知的基线失败，不将其写成通过。
3. 更新本次发布记录，说明用户可见变化、验证范围、生产数据或数据库是否变更。
4. 提交选定文件并推送到 GitHub。记录提交 SHA；不得把凭据、用户对话、数据库转储或原始含身份信息的访问日志推入仓库。
5. 从 ECS 实时读取 /opt/guoke/current、服务状态、部署配置指纹和磁盘空间。按这些值建立只含本次文件的 SHA-256 发布清单。旧发布包的基线过期时必须重新生成。
6. 上传发布包后依次执行 python3 ops/release.py preflight、python3 ops/release.py stage --apply、python3 ops/release.py activate --apply。暂存过程应在独立端口完成构建、测试和 HTTP 检查；本项目一般更新不执行数据库迁移或全量种子。
7. 验收 /games、本次游戏页、/api/ai-chat、语音合成接口和关键静态资源；核对 current 指向候选版本，guoke-web、Nginx 和 PostgreSQL 正常。失败时保留证据并按发布脚本回滚。
8. 将提交 SHA、发布包 SHA-256、前后版本、测试结果、线上 HTTP/服务检查、磁盘清理结果和未覆盖事项补入发布记录，再推送记录更新。

## 磁盘与缓存

每次发布前后检查 df -h 和关键目录大小，至少保留当前版本、上一回滚版本、数据库备份和发布状态目录。候选发布失败目录先保留故障摘要；查明并确认不再需要后，才清理归档。

当前版本的 .next/cache 是运行缓存，必须存在并由 guoke 服务用户读写；不要在服务运行时清空。旧版本缓存只有在空间回收有实际需要、且保留回滚版本内容后才清理；清理后为回滚准备好空缓存目录及正确权限。只删除确认过期且不被进程占用的 /tmp 暂存文件。Nginx、systemd 日志按服务器 logrotate/journald 配置轮转；需要缩减 journal 时先记录大小和保留策略。

发布记录、清单和脱敏后的错误摘要存 GitHub。原始访问日志、对话正文、账号资料、凭据和数据库备份只放受控的服务器备份位置，不复制到公开或普通 Git 历史。

## 回滚与清理检查

- 先验证当前版本和候选版本路径，不依据目录名称猜测当前版本。
- 保留上一可用版本及其独立数据库备份；本项目只加表或兼容字段的变更也不得用旧整库覆盖新业务数据。
- 清理前记录目标绝对路径、用途、大小及是否被服务引用；清理后复查服务状态、磁盘空间和关键路由。
- 发布成功不能代替线上验收；至少检查页面、AI 对话、语音音频响应和游戏交互。
