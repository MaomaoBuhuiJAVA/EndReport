## 通过标准

- [ ] 9 个原始样例均能返回中文回答，不出现工作流错误；
- [ ] 1、2、4、5、6、9 的回答能从知识库命中对应类别和年龄段；
- [ ] 2 的完整教案包含活动过程，而不只返回目标和准备；
- [ ] 3 能正确说明当前 Chat-only 模型不能直接识图，并给出文字描述补充路径；
- [x] 6 的视频、二维码和详情链接来自同一实验并已在公开回答中返回；
- [ ] 9 的步骤图片链接真实可打开且顺序正确；
- [x] 10 的教学请求不暴露 DeepSeek 内部推理正文；
- [x] 11 的无文件 PPT 课件创作经过策划、审核和交付三节点；
- [ ] 12 的上传文档解析全链路通过无敏感样例复测；
- [x] 13 的 URL 上传文档解析经过提取、分析、审核和交付全链路；
- [ ] 7 能保持上下文并正确切换年龄难度；
- [ ] 8 不编造资料库外的事实；
- [ ] 火焰掌等火源实验始终只给教师演示边界，不指导幼儿直接操作。

## 多模态边界

当前工作流的多模态能力是“文本提问 + 检索并回传公开图片、视频、二维码链接”。`deepseek-v4-pro` 在当前 Dify 提供方中没有视觉输入能力，不能把上传图片当作已被模型识别的内容。若要增加真正的图像理解，需要在 Dify 中新增支持视觉的模型节点，或先用图像识别/OCR 节点把结果转成文本，再传给科小贝；完成后把第 3 条改回图像理解验收并重新发布。

## 回归命令

在本地项目目录执行：

```powershell
node --test scripts/export-dify-teaching-knowledge.test.mjs
npm run export:dify
npm test -- --run
npx tsc --noEmit
```

导出契约应显示 3/3 通过，并重新生成 13 个 Markdown 文件、包含 160 条资料。若公开域名或资源路径变化，先重新运行导出器，再重新上传受影响的文档。
