# 科小贝语音播报与实时通话设计

日期：2026-08-16

## 目标

在现有科小贝文字对话不变的前提下，增加两项能力：

- 助手回复气泡提供复制和语音播报操作，播报固定使用豆包 `x4_doudou` 音色。
- 对话框右上角提供电话入口，进入持续聆听、自动回答、语音播报、继续聆听的半双工通话模式。

## 方案与边界

采用“服务端豆包 TTS 代理 + 浏览器语音识别”的方案。

- 浏览器继续使用已有的中文 `SpeechRecognition` 能力获取用户语音，避免把豆包凭证暴露给客户端。
- 服务端新增语音合成路由，使用 WebSocket 连接豆包双向 TTS 接口，固定传入 `x4_doudou`，返回 `audio/mpeg`。
- 通话每轮复用现有 `/api/ai-chat`，所以资料库检索、DeepSeek 回复、实验详情链接和文字兜底保持一致。
- Vercel Serverless 不承载浏览器到豆包的长连接；每次播报使用一次短生命周期的服务端 WebSocket 请求。通话长生命周期只存在于浏览器状态机中。

## 交互设计

### 回复气泡

- 仅助手消息显示操作栏，用户消息保持原样。
- “复制”写入完整纯文本回复，成功后短暂显示“已复制”，失败显示可读提示。
- “喇叭”首次点击请求 `/api/voice/tts` 并播放音频；播放中再次点击停止。任意新播报会停止上一个音频。
- 语音失败只提示“语音暂时不可用”，不影响文字回复和资源跳转。

### 电话面板

- 标题栏右上角加入电话图标；点击后打开通话面板。
- 打开面板时申请麦克风权限并启动中文连续识别。
- 状态依次为“准备麦克风”“正在聆听”“正在整理”“科小贝回答中”“正在播报”；播放期间暂停识别，音频结束后自动恢复。
- 面板提供静音、结束通话和关闭按钮，显示最近一轮识别文字和助手回复。
- 浏览器不支持识别、权限拒绝或服务断开时，保留文字输入并显示明确状态，不阻塞普通对话。
- 结束通话会停止识别、停止音频、释放麦克风轨道并清理事件监听。

## 服务端接口

`POST /api/voice/tts`

请求体：

```json
{ "text": "要播报的中文内容" }
```

响应：

- 成功：`200 audio/mpeg`，带 `Cache-Control: no-store`。
- 参数缺失：`400`。
- 未配置或豆包调用失败：`503` JSON 错误，不泄露凭证和上游详细信息。

服务端变量只使用非公开名称，例如 `DOUBAO_APP_ID`、`DOUBAO_API_KEY`、`DOUBAO_API_SECRET`、`DOUBAO_TTS_RESOURCE_ID`；不使用 `NEXT_PUBLIC_` 前缀，不写入仓库或返回给浏览器。默认音色为 `x4_doudou`，资源 ID 支持通过环境变量覆盖。

## 数据流

1. 用户点击复制或喇叭。
2. 喇叭操作向服务端发送回复文本；服务端建立豆包 WebSocket、完成鉴权和 TTS 事件握手，收集音频帧后返回。
3. 电话模式中，浏览器识别到一句最终文本后调用 `/api/ai-chat`；收到回复后调用同一 TTS 路由并播放。
4. 播放结束触发下一轮识别；所有异常回到文字输入或可重试状态。

## 测试与验收

- 单元测试覆盖：TTS 请求校验、音色/密钥只在服务端使用、豆包帧解析、上游错误映射、复制状态和播报停止逻辑。
- 组件契约测试覆盖：气泡操作栏、电话按钮、通话状态、无语音能力降级。
- 运行 TypeScript、Lint、全量 Vitest、科学资源契约测试和生产构建。
- 浏览器验收桌面与手机视口：打开电话、授予/拒绝麦克风、连续一轮问答、静音、结束通话、复制和语音播报。

## 明确不做

- 不把 AppID、APIKey、APISecret 写入前端 bundle、Git、日志或 API 响应。
- 不改变现有资料库检索、DeepSeek 对话和实验详情跳转协议。
- 不在 Vercel 上维护跨请求的永久 WebSocket；每轮语音请求独立关闭。
